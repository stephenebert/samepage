SamePage vs plain Meta review — pre-registered small comparison
Prepared 2026-10-27 before any benchmark model requests.

QUESTION
Does the existing SamePage interpretation-plus-checker pipeline identify bilingual policy outcome differences more reliably than a competent natural-language review by the same Meta model?
This measures policy-pair review, not autonomous repair quality, general AI safety, human usability, or a complete end-to-end product comparison.

DATA
12 fresh synthetic English/Spanish policy pairs, authored by an independent assistant agent: 6 different, 4 behaviorally equivalent, 2 requiring clarification or outside the executable domain. A separate assistant audits English/Spanish semantics and independently written reference functions before the test. This is independent AI review, not human bilingual validation.
Provider receives only the frozen source policy pair, not expected labels, reference implementations, examples of correct answers, or test attendees. Generic case IDs and mixed ordering avoid label leakage.
All source policies, reference outputs, oracle, prompts, model settings, scoring, and execution order are hashed before the first provider request. No tuning, retries, replacements, or case exclusions after outcomes are observed.

ARMS
SamePage: existing production interpreter and deterministic consequence discovery. muse-spark-1.3, expression-v3, low reasoning, no reuse, maximum8192 completion tokens. Existing source commit9d7b0c5755de3465610a592cfccd83bfd4d3ba7b is the subject; benchmark transport does not change its interpreter/checker.
Plain Meta: same model, low reasoning, maximum8192 completion tokens, shared policy-as-untrusted-data system message. A competent natural-language review prompt supplies the same supported domain and semantic requirements, including ambiguity/unsupported-clause handling. Structured response requests classification, concise explanation, issues, and one concrete example of differing outcomes. No rule AST, execution tools, or deterministic checker is given to this arm.
One request per arm per pair,24 total maximum. Alternating which arm runs first balances order. Each request has an independent context, no prior cases or outputs. SamePage's fuller schema/translation overhead is reported as part of its real cost; the baseline is not padded artificially.

PRIMARY SCORING
Three-class accuracy: different/equivalent/unresolved, against frozen expected labels. A provider error, refusal, timeout, malformed/incomplete response, or invalid schema is an error, never silently converted into an appropriate clarification. All cases remain in denominator; unexecuted cases are identified separately if infrastructure forces early termination.
Also report harmful differences detected out of6; false alarms and unnecessary abstentions among4 equivalent pairs; correct clarification among2 unresolved pairs. 'Different' earns detection credit separately from whether its example is correct.

SECONDARY SCORING
Concrete evidence: a reported attendee must have genuinely different outcomes under the independent oracle, and both reported acceptance/fee outcomes must be correct. Report at least one valid witness per different case and all witness errors.
SamePage interpretation fidelity: separately evaluate each compiled policy against the direct oracle over all integer ages0–120, all32 boolean combinations, and every interval/boundary represented by the union of source and returned-model timestamp boundaries plus adjacent milliseconds. A correct pair label does not excuse an incorrect policy interpretation. Include handpicked source examples. Do not call this source-language proof.
Executable workflow: offline replay actual returned SamePage interpretations through production state reducers. Simulated Alice and Bob save their drafts; one approval cannot publish; divergent choices cannot publish; joint selection publishes a selected complete candidate; receipt outcomes match the independent oracle. Unresolved candidates cannot publish. This is supplemental SamePage verification, not a feature metric assigned against the plain-review arm.
Report provider and complete-operation latency separately, individual token usage, and uncached-rate usage estimates for both arms. No invented provider billing figures or unmeasured human-time savings.

Ordinary model interpretation errors remain in results and do not trigger retries.

INTERPRETATION
This is one small, synthetic, in-domain challenge set with no human validation and one sample per arm/case. Report paired wins/losses/ties and every failure. Do not claim statistical superiority, universal correctness, novelty, or hackathon winning probability. A tie is a tie; failures are useful evidence, not reasons to redesign the test after seeing outputs.
